## 这个故事

我把这场比赛当成检验会计基础的节点来打。完整版（含面试 90 秒口述稿）见 [简历故事.md](./简历故事.md)，行动链如下：

```
公开渠道获取历届题库（1,000 + 483 题两个来源）→ 合并去重成 1,472 题
  → 按题型分布锁定重点：企业会计 + 政府会计占大头，策略从"全看"变"重点突破"
  → 人机并行：Claude Code 后台逐题写深度解析+记忆口诀；我同步刷完初级会计实务 700 题
  → 每题打知识点标签，同类聚合并按频次排序——复习顺序变成数据驱动
  → 结构再升级：每个模块"先集中讲解（口诀+生活化例子）、后例题"，题库变教材
  → 考前二分："理解攻坚"与"死记突击"两套资料 + 考前一页纸，明确跳过长投/租赁等低频难点
  → 导出 Word 发全队，统一备赛
```

一个人备赛是学习，**把全队武装起来才是队长的工作**。

## 每份文档的 5 段结构（`markdown/`）

1. **知识框架总览** — 思维导图式全貌
2. **核心考点精讲** — 定义 + 对比表格 + 记忆口诀
3. **易错陷阱 TOP 10** — "错误说法 vs 正确说法"对比
4. **核心要点速查表** — 关键数字/比例/期限，考前速刷
5. **全部题目练习** — 附答案和出处

## 仓库结构

- `markdown/` — 13 份模块解析 + 总复习（AI 生成、我校对后的 md 源文件）
- `word/` — 发给队友的 Word 成品（含考前突击速成手册、"先讲解后刷题"样板）
- `archive/` — 完整过程档案，证明这套资料是怎么被工程化造出来的：
  - `scripts/` — 24 个 Python 脚本：题目解析（parse）→ 归类拼装（build）→ 独立校验（validate）→ md 转 Word（md2docx，可复用）
  - `data/` — 1,472 题的结构化 JSON 数据源（no / 标签 / 题型 / 题干 / 答案）
  - `knowledge-points/` `review-cards/` `lectures/` — 知识点清单、模块复习卡、企业会计准则 12 讲讲解稿
  - `master/` `crash/` `sample/` — 全模块汇总、考前突击手册、讲解版样板的 md 源文件

**质量记录**：重排后与原题库逐字比对零差异（validate.py 独立校验，不依赖 AI 自述）；每题恰好归属一个模块；原文错放在"单选题"章节的判断题已按标签前缀校正为真实题型。详见 [archive/README.md](./archive/README.md)。

## 这个故事里最值钱的三个点

1. **数据驱动决策**：先看题库分布定策略、再按知识点频次排序定复习顺序，不凭感觉
2. **人机分工**：批量写解析交给 AI，打地基刷题自己来，两条线并行互不阻塞
3. **懂得放弃**：跳过长投、租赁——备赛是约束条件下的得分最大化，不是知识覆盖最大化
